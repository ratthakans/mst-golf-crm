Reading sales bills from the POS

MST Golf runs a membership system: members earn points on what they buy. To give points automatically, our system needs to read the store's bills from the POS through an API. This page lists what we need.

We only readOur system calls your API. We never create, change or delete anything in the POS.
Every 15 minutesWe ask for the bills that are new or changed since our last check.
No webhooksYou don't need to send anything to us or call our system.

1. Access

LoginAn API key (or OAuth 2.0 client credentials) that can only read bills, limited to MST Golf's store.
FormatHTTPS and JSON. Dates with a time zone (ISO 8601, e.g. 2026-10-15T18:42:10+07:00). Money as numbers with 2 decimals.
IP addressOur system runs in the cloud and has no fixed IP, so please don't require an IP whitelist.
HistoryWe need to read at least the last 13 months of bills once, when we start.
Not neededCard numbers, or any customer data other than the member's phone number or member code typed on the bill.

2. Endpoints

Endpoint (example name)What we use it forNeed
GET /bills?updated_since=…Bills created or changed after a given time. This must include refunds, voids and bills that reached the server late (e.g. after the internet was down). Paged.Required
GET /bills?from=…&to=…Bills by sale date. Used once to load past sales, and to re-read a day if needed.Required
GET /bills/{id}One bill, to check when a customer asks about their points.Nice to have
GET /productsProduct brand and category, if bills don't include them.Nice to have

Your field and endpoint names don't have to match ours — just tell us the real names in your API documentation.

What each bill needs to contain

Everything is required unless marked (nice) — nice to have.

3. Bill

bill_noUnique, and never changes after the bill is closed. We use it to never give points twice.
typeSale, refund or void.
ref_bill_noFor refunds and voids: the original sale's bill number.
sold_at, updated_atWhen it was sold, and when it was last saved or changed.
statusClosed, on hold or cancelled. We only count closed bills.
branch, terminalWhich store and which till.
gross, discount, netTotal before discount, bill discount, amount paid. Say whether VAT is included.
member_refMember's phone or member code. A separate field is best; the bill remark also works (staff type MSTMEMBER:0891112233).
remarkThe bill's note, in full.
payments (nice)Payment methods and amounts.

4. Items on the bill

sku, nameProduct code and name.
qty, unit_priceQuantity and price each.
line_discount, line_netDiscount on the item and the item's total.
brand, category (nice)Lets the store exclude some products from points.
item_type (nice)Marks gift cards, vouchers and services.
ref_line (nice)For a partial refund: which item was returned.

To get started, please send

  • Your full API documentation
  • A test environment (sandbox) and a test API key
  • One real example each: a sale, a refund, a void

ภาพรวม

MST Golf Platform คือระบบสมาชิกของร้าน: ลูกค้าสะสมแต้มจากยอดซื้อ ระดับสมาชิกคิดจากยอดซื้อ 12 เดือน และได้ข้อความแจ้งแต้มทาง LINE · ตอนนี้ระบบรับยอดขายจากไฟล์ CSV ที่ export จาก POS วันละครั้ง เราต้องการเปลี่ยนเป็น ดึงข้อมูลบิลผ่าน API ของ POS เป็นรอบอัตโนมัติ เพื่อให้แต้มเข้าภายในไม่กี่นาทีหลังลูกค้าชำระเงิน

รูปแบบการเชื่อมต่อ: MST Golf Platform ดึงข้อมูลอย่างเดียว

  • ทิศทางเดียว (pull): ระบบของเราเรียก API ของ POS เพื่ออ่านบิล · POS ไม่ต้อง ส่ง webhook และ ไม่ต้อง เรียกระบบของเรา
  • อ่านอย่างเดียว (read-only): เราไม่สร้าง แก้ หรือลบข้อมูลใด ๆ ใน POS · ขอ API key ที่มีสิทธิ์อ่านบิลอย่างเดียว เฉพาะสาขาของ MST
  • รอบการดึง: ทุก 15 นาที และดึงย้อนทับช่วงเวลาของรอบก่อนเล็กน้อย บิลที่รับไปแล้วระบบข้ามเอง
  • ไฟล์ CSV ยังใช้ต่อ เป็นทางสำรองเมื่อ API ไม่พร้อมใช้งาน
1ลูกค้าชำระเงินพนักงานใส่เบอร์หรือรหัสสมาชิกในบิล แล้วปิดบิลตามปกติ
2POS เก็บบิลบิลพร้อมให้อ่านผ่าน API (ระบุว่าช้ากว่าเวลาจริงเท่าไร)
3เราดึงทุก 15 นาทีขอบิลที่ updated_since เวลาล่าสุดที่เคยดึง
4ลูกค้าได้แต้มระบบคำนวณแต้ม ระดับ และส่งข้อความ LINE

สิ่งที่ขอจากผู้ให้บริการ POS

  1. เอกสาร API ฉบับเต็ม (endpoint · การยืนยันตัวตน · โครงสร้างข้อมูล · error code)
  2. ระบบทดสอบ (sandbox) หรือสาขาทดสอบ พร้อม API key สำหรับทดสอบ
  3. คำตอบของคำถามในหน้า 3 (ช่อง "คำตอบ")
  4. ตัวอย่าง response จริง (JSON) ตามรายการในหน้า 4 — ลบข้อมูลส่วนตัวลูกค้าออกได้
  5. ค่าใช้จ่ายการเปิดใช้ API (ถ้ามี) และผู้ติดต่อด้านเทคนิค

หลักการเรื่องข้อมูล

เราต้องการเฉพาะข้อมูลที่ใช้คำนวณแต้มและยอดซื้อ (หน้า 2) · ไม่ต้องการข้อมูลบัตรชำระเงิน ข้อมูลพนักงานเกินชื่อ/รหัส หรือข้อมูลลูกค้าอื่นนอกจากเบอร์/รหัสสมาชิกที่ร้านใส่ในบิล · ข้อมูลส่งผ่าน HTTPS เท่านั้น และ API key เก็บแบบเข้ารหัสในระบบของเรา

POS API Requirements

ข้อมูลที่ต้องอ่านได้จาก API

ชื่อฟิลด์ไม่ต้องตรงตามตาราง — ขอให้มีข้อมูลเทียบเท่า และระบุชื่อฟิลด์จริงในเอกสาร API · จำเป็น = ขาดไม่ได้ · ควรมี = ช่วยให้ข้อมูลครบขึ้น

1. Endpoint ที่ต้องมี

Endpointใช้ทำอะไรระดับ
GET /bills?updated_since=…รายการบิลที่ถูกสร้าง หรือแก้ไข หลังเวลาที่กำหนด (รวมบิลคืน บิลยกเลิก และบิลที่ส่งเข้าระบบช้า) · แบ่งหน้าด้วย cursor หรือ pageจำเป็น
GET /bills?from=…&to=…บิลตามช่วงวันที่ขาย — ใช้ดึงยอดย้อนหลัง 12 เดือนครั้งเดียวตอนเริ่ม และดึงซ่อมเมื่อระบบเราขัดข้องจำเป็น
GET /bills/{id}รายละเอียดบิลเดียว (ใช้ตรวจสอบเมื่อลูกค้าสอบถาม)ควรมี
GET /productsข้อมูลสินค้า (SKU · ชื่อ · ยี่ห้อ · หมวด) ถ้าบิลไม่ได้ส่งยี่ห้อ/หมวดมาด้วยควรมี
GET /branchesรหัสและชื่อสาขา/เครื่อง POSควรมี

2. ข้อมูลระดับบิล

ข้อมูลรายละเอียดระดับ
bill_id / bill_noไม่ซ้ำ และไม่เปลี่ยนหลังปิดบิล — ระบบเราใช้กันแต้มเข้าซ้ำจำเป็น
typeขาย / คืนสินค้า / ยกเลิกบิลจำเป็น
ref_bill_noบิลคืนหรือยกเลิก ต้องอ้างถึงเลขบิลขายเดิมจำเป็น
sold_at · updated_atเวลาขาย และเวลาที่บิลถูกบันทึกหรือแก้ไขล่าสุด พร้อม timezone (ISO 8601)จำเป็น
statusปิดแล้ว / พักบิล / ยกเลิก — เราจะนับเฉพาะบิลที่ปิดแล้วจำเป็น
branch_code · terminalสาขาและเครื่องที่ออกบิลจำเป็น
gross · discount · net · vatยอดก่อนลด · ส่วนลดท้ายบิล · ยอดสุทธิที่ลูกค้าจ่าย · VAT (ระบุว่ายอดรวม VAT แล้วหรือไม่)จำเป็น
member_refเบอร์มือถือหรือรหัสสมาชิกที่พนักงานใส่ — ช่องเฉพาะ ดีที่สุด · ถ้าไม่มี ใช้หมายเหตุบิลที่พิมพ์ MSTMEMBER:0891112233 ได้จำเป็น
remarkหมายเหตุบิล (ข้อความเต็ม)จำเป็น
payments[]วิธีชำระและจำนวนเงินแต่ละวิธี (ไม่ต้องมีเลขบัตร)ควรมี
cashierชื่อหรือรหัสพนักงาน — ใช้ติดตามบิลที่ลืมใส่เบอร์สมาชิกควรมี

3. ข้อมูลรายการสินค้าในบิล (lines[])

ข้อมูลรายละเอียดระดับ
sku · nameรหัสและชื่อสินค้าจำเป็น
qty · unit_priceจำนวนและราคาต่อหน่วยจำเป็น
line_discount · line_netส่วนลดของรายการและยอดสุทธิของรายการจำเป็น
brand · categoryยี่ห้อและหมวดสินค้า — ใช้กำหนดสินค้าที่ไม่ได้แต้มควรมี
item_typeบอกได้ว่าเป็นบัตรกำนัล / คูปอง / ค่าบริการ — ไม่ควรได้แต้มควรมี
ref_line (บิลคืน)คืนบางรายการ: ระบุรายการที่คืนและจำนวนควรมี

POS API Requirements

คำถามถึงผู้ให้บริการ POS

กรุณาตอบในช่อง "คำตอบ" หรือแนบเอกสารอ้างอิง

#คำถามคำตอบ
ระบบและการเข้าถึง
1ยี่ห้อ รุ่น เวอร์ชันของ POS · เป็นระบบ cloud หรือติดตั้งในร้าน
2ยืนยันตัวตนแบบใด (API key / OAuth 2.0) · token มีอายุเท่าไร ต่ออายุอย่างไร
3ออก API key ที่ อ่านอย่างเดียว และจำกัดเฉพาะสาขา MST ได้ไหม
4บังคับ IP whitelist ไหม — ระบบเราอยู่บน cloud ที่ IP ไม่คงที่ ถ้าบังคับขอทางเลือกอื่น
5จำกัดจำนวนคำขอ (rate limit) ต่อนาที / ต่อวัน เท่าไร · ดึงได้หน้าละกี่บิล
6มีค่าใช้จ่ายการใช้ API ไหม · ใครเปิดสิทธิ์ · ใช้เวลาเปิดกี่วัน
ความครบถ้วนของข้อมูล
7หลังปิดบิล บิลพร้อมให้อ่านผ่าน API ช้าสุดกี่นาที
8ถ้าอินเทอร์เน็ตในร้านล่ม บิลที่ส่งเข้าระบบทีหลังจะมี updated_at เป็นเวลาที่ส่งเข้าระบบใช่ไหม (เพื่อไม่ให้ดึงตก)
9แก้บิลหลังปิดแล้วได้ไหม · ถ้าได้ เลขบิลเดิมหรือออกเลขใหม่ · updated_at เปลี่ยนไหม
10บิลคืนสินค้า: คืนบางรายการได้ไหม · ระบุรายการที่คืนได้ไหม · เลขบิลคืนแยกจากบิลขายไหม
11ยกเลิกบิล: เป็นบิลใหม่ที่อ้างบิลเดิม หรือเปลี่ยนสถานะบิลเดิม
12ดึงข้อมูลย้อนหลังได้ไกลสุดกี่เดือน
สมาชิกและสินค้า
13มีช่องเฉพาะสำหรับเบอร์หรือรหัสสมาชิกไหม · ช่องนี้สแกน QR / barcode ได้ไหม · ถ้าไม่มี ใช้หมายเหตุบิลได้ไหม
14ยอดในบิลรวม VAT แล้วหรือไม่ · ส่วนลดท้ายบิลกระจายลงแต่ละรายการไหม
15แยกบัตรกำนัล คูปอง และค่าบริการ ออกจากสินค้าได้ไหม (ไม่ควรได้แต้ม)
การดูแล
16มีการแจ้งล่วงหน้าเมื่อเปลี่ยนเวอร์ชัน API ไหม · API เดิมใช้ได้อีกนานเท่าไร
17ช่องทางและเวลาตอบเมื่อ API มีปัญหา · หน้าแสดงสถานะระบบ (status page)
18ผู้ติดต่อด้านเทคนิค (ชื่อ · อีเมล · โทร)

ขอ response จริงอย่างละ 1 บิล

  • บิลขายที่มีสมาชิก · บิลที่ไม่มีสมาชิก
  • บิลที่มีส่วนลดท้ายบิล · บิลที่จ่ายหลายวิธี
  • บิลคืนบางรายการ · บิลยกเลิกทั้งใบ
  • บิลที่ถูกแก้ไขหลังปิดบิล (ถ้า POS อนุญาต)
  • บิลที่มีบัตรกำนัลหรือคูปอง

ขั้นตอนทดสอบร่วมกัน

  1. ผู้ให้บริการ POS ส่งเอกสาร API · sandbox · API key ทดสอบ · คำตอบหน้า 3
  2. ORIONS เชื่อมต่อกับ sandbox และดึงบิลตัวอย่างทุกประเภท
  3. ทดสอบที่ร้านจริง 1 วัน: ออกบิลขาย คืน ยกเลิก แล้วเทียบยอดในระบบสมาชิกกับรายงานปิดวันของ POS ให้ตรงกันทุกบาท
  4. เปิด API key จริง (อ่านอย่างเดียว) แล้วเปลี่ยนจากไฟล์ CSV เป็น API — CSV ยังเก็บไว้เป็นทางสำรอง

สิ่งที่ระบบเราทำเมื่อได้ข้อมูล

  • บิลเดียวกันได้แต้มครั้งเดียว ไม่ว่าจะดึงซ้ำกี่รอบ
  • บิลคืน/ยกเลิก หักแต้มตามสัดส่วนของบิลเดิม
  • บิลที่ไม่มีสมาชิก นับเป็นยอดขายของร้าน ไม่มีใครได้แต้ม
  • บันทึกผลทุกรอบการดึง และแสดงสถานะในหลังบ้านของร้าน

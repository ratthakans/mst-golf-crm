## 1 · ภาพรวม

**MST Golf Platform** คือระบบสมาชิก แต้มสะสม และจองซิมกอล์ฟของ MST Golf Thailand (ชาญอิสสระ ทาวเวอร์ 1) เป็นแพลตฟอร์มของ ORIONS ที่ MST เป็น tenant แรก

| ผู้ใช้ | ใช้ผ่าน | ทำอะไร |
|---|---|---|
| ลูกค้า | เว็บไซต์ (มือถือ) — เข้าสู่ระบบด้วยเบอร์ + รหัส SMS | สมัครสมาชิก · บัตรสมาชิก QR · ดูแต้มและระดับ · จองซิม · แลกรางวัล · การแจ้งเตือนบนเว็บ (+ อีเมล) |
| พนักงาน MST (5 ตำแหน่ง) | หลังบ้าน | เพิ่มสมาชิก · นำเข้ายอดขาย POS · ตารางซิม · บทความเว็บ · ตั้งค่า |
| ทีม LINE Marketing | LINE OA Manager | Rich Menu · auto reply · แชต · บรอดแคสต์ — ไม่ต้องแตะระบบนี้ · ระยะแรกไม่เชื่อม LINE (§8) |

ลูกค้า 1 คน = รหัสสมาชิกเดียว (`MST00000001`) ผูกกับเบอร์มือถือ (และ LINE UID เมื่อเปิดใช้ LINE) ไม่ว่าเข้ามาทางไหนก็เป็นคนเดิม

## 2 · สถาปัตยกรรม

```
ลูกค้า (เบราว์เซอร์มือถือ) ── เบอร์ + รหัส SMS ──┐     SMS (ThaiBulkSMS) · อีเมล (Resend)
   [LINE OA / LIFF — มีโค้ดแล้ว ปิดไว้ features.line]  │
                                                    ▼
┌────────────────────────────┐        ┌────────────────────────────────┐
│ apps/web-admin  (หลังบ้าน)  │        │ apps/web  (เว็บไซต์ + หน้าลูกค้า) │
│ Vercel "mst-golf-crm"      │        │ Vercel "mst-golf-web"          │
│ /api/*  /api/cron/*        │        │ /  /services  /golf-simulator  │
│                            │        │ /rewards /promotions /contact  │
│                            │        │ /blog /app/member /app/booking │
│                            │        │ /app/rewards /app/inbox        │
└─────────────┬──────────────┘        └───────────────┬────────────────┘
              └──────────── packages/core ───────────┘
                 ตรรกะธุรกิจทั้งหมด (สมาชิก แต้ม ระดับ POS จอง รางวัล การแจ้งเตือน)
                              packages/database (Prisma, forOrg)
                              Neon Postgres · Singapore
```

- **สองแอป หนึ่งแกนกลาง** — route handler แค่ตรวจสิทธิ์แล้วเรียก `@mstgolf/core` ทุกกติกาอยู่ที่เดียว ทดสอบได้โดยไม่ต้องมีเว็บ
- **Multi-tenant** — ทุกตารางมี `orgId` ทุก query ผ่าน `forOrg(orgId)` แอปรู้ว่าเป็นร้านไหนจาก `ORG_SLUG`
- **ฐานข้อมูลแยกตามสภาพแวดล้อม** — Neon ฐานเดียว แยก Postgres schema: `public` = production · `preview` · `dev` · `test_core`

### การยืนยันตัวลูกค้า

```
/register · /login → /app/member
ใส่เบอร์มือถือ → POST /api/me/otp        ส่งรหัส 6 หลักทาง SMS (เก็บแค่ hash · 5 นาที · ผิดได้ 5 ครั้ง
                                          · ขอใหม่ได้ทุก 60 วิ · วันละ 5 ครั้ง/เบอร์ · 20 ครั้ง/ชม./IP)
ใส่รหัส     → POST /api/me/otp/verify
   ├ เบอร์เป็นสมาชิกแล้ว (สมัครเอง หรือพนักงานสมัครให้ที่เคาน์เตอร์) → cookie mst_member = รหัสสมาชิก (30 วัน)
   └ ยังไม่เป็น (รวมสมาชิกที่มาจาก POS) → cookie "เบอร์ยืนยันแล้ว" 30 นาที → ฟอร์มสมัคร (เบอร์ล็อกไว้)
ทุก /api/me/* หาสมาชิกจาก cookie เท่านั้น ไม่รับ id จาก request
```

- **ตอนนี้ปิดการยืนยันด้วย SMS อยู่ (`settings.features.otp = false`, ตัดสินใจ 12 ต.ค. — เน้นทดสอบ flow ก่อน):** ใส่เบอร์อย่างเดียวก็เข้าบัญชี/สมัครได้ (`POST /api/me/phone`) · เบอร์ที่สมัครแบบนี้ไม่ถูกนับว่า "ยืนยันแล้ว" · เปิดที่ ตั้งค่า › เว็บไซต์และร้าน — **ต้องเปิดก่อนเปิดใช้จริง** (ความพร้อมเปิดใช้แสดงเป็นข้อค้าง)
- ยังไม่มีบัญชีผู้ให้บริการ SMS: เครื่อง dev / preview ใช้โหมดทดสอบที่แสดงรหัสบนจอ (ไม่ทำงานกับฐาน production) · production ปฏิเสธจนกว่าจะตั้ง `SMS_PROVIDER` + key
- เมื่อเปิด LINE (`settings.features.line`) หน้าเดียวกันแสดงปุ่มเข้าสู่ระบบด้วย LINE เพิ่ม และ cookie LINE เดิมยังใช้ได้

## 3 · ระบบสมาชิก

### 3.1 หน้าลูกค้า (`/app/member`)

| สถานะ | แสดง |
|---|---|
| ยังไม่ล็อกอิน | เบอร์มือถือ → รหัส SMS |
| ยืนยันเบอร์แล้ว ยังไม่เป็นสมาชิก | ฟอร์มสมัคร: ชื่อ-นามสกุล · เบอร์มือถือ (ยืนยันแล้ว แก้ไม่ได้) · วันเกิด (ไม่บังคับ — ได้แต้ม ×2 เดือนเกิด) · อีเมล (ไม่บังคับ) · ยอมรับข้อกำหนด (บังคับ) · รับข่าวสาร (เลือกได้) |
| สมาชิก | แท็บ **บัตร**: ชื่อ ระดับ รหัส QR แต้ม แถบ "อีก ฿X ถึง Silver" ปุ่มเพิ่มความสว่างสำหรับสแกนที่เคาน์เตอร์ · **แต้ม**: ประวัติพร้อมเหตุผล · **โปรไฟล์**: แก้ชื่อ อีเมล วันเกิด (ครั้งเดียว) ส่งแจ้งเตือนทางอีเมล รับข่าวสาร · กระดิ่งมุมขวาบน = **การแจ้งเตือน** (`/app/inbox`) |

### 3.2 กติกาการสมัคร

```
เบอร์ → ทำให้เป็น 0XXXXXXXXX (06/08/09) ไม่งั้น "เบอร์ไม่ถูกต้อง"
สมัครบนเว็บต้องยืนยันเบอร์ด้วยรหัส SMS ก่อนเสมอ
├ เบอร์ใหม่                          → สร้างสมาชิก + เบอร์ (ยืนยันแล้ว) + แต้มต้อนรับ
├ เบอร์มีอยู่ มาจาก POS (ยังไม่เคยสมัคร) → เป็นบัญชีเดิม: ได้แต้ม ประวัติ ระดับเดิม · แต้มต้อนรับให้ครั้งเดียวต่อคน
└ เบอร์มีอยู่ สมัครแล้ว/สมัครที่เคาน์เตอร์ → ไม่ต้องสมัคร เข้าสู่ระบบได้เลย
(เมื่อเปิด LINE: เบอร์ที่ผูก LINE อื่นแล้ว → ไม่ผูก แจ้ง "ติดต่อร้าน" + เข้าคิวตรวจสอบ)
```

- เบอร์ **ยืนยันแล้ว** เมื่อบิลแรกที่มีเบอร์นี้เข้าระบบ หรือพนักงานสร้าง/แก้ให้ที่เคาน์เตอร์ (ไม่มี OTP)
- ทุกการสมัครบันทึกความยินยอม TERMS + MARKETING พร้อมเวอร์ชันข้อความที่ลูกค้าเห็นจริง
- ช่องทางที่มา: `LINE` · `WEB` · `COUNTER` · `POS` · `IMPORT`

### 3.3 แต้มและระดับ

| | ค่าตั้งต้น (แก้ได้ใน ตั้งค่า) |
|---|---|
| แต้มต้อนรับ | 1,600 |
| แต้มฐาน | ตั้งเป็น "ยอดซื้อทุก ฿X ได้ Y แต้ม" — ค่าตั้งต้น ฿1 = 1 แต้ม, ข้อเสนอของ MST คือ ฿500 = 1 แต้ม (ยอดสุทธิ ไม่รวมสินค้าที่ตั้งยกเว้น · คิดต่อบิล ปัดเศษลง) |
| อัตราตามระดับ | Member ×1 · Silver ×1.25 · Gold ×1.5 |
| เดือนเกิด | แต้มฐาน ×2 (ต้องมีวันเกิดในโปรไฟล์) |
| Silver | ยอดซื้อ 12 เดือน ≥ ฿100,000 · ส่วนลดร้าน 5% · ส่วนลดซิม 10% · จองล่วงหน้า 14 วัน |
| Gold | ยอดซื้อ 12 เดือน ≥ ฿1,000,000 · ส่วนลดร้าน 10% · ส่วนลดซิม 20% · จองล่วงหน้า 21 วัน |

```
แต้มบิล = floor(ยอดที่ได้แต้ม × แต้มต่อบาท × อัตราของระดับ "ก่อน" บิลนี้)
        + แต้มฐาน × (ตัวคูณเดือนเกิด − 1)   ถ้าเป็นเดือนเกิด
```

- **ระดับคิดจากยอดซื้อสุทธิ 12 เดือนย้อนหลัง ไม่ใช่แต้มคงเหลือ**
- **ขึ้นทันที** เมื่อบิลทำให้ถึงเกณฑ์ (บิลที่ทำให้ขึ้นได้อัตราเดิม บิลถัดไปได้อัตราใหม่) + ข้อความ LINE
- **ลงเดือนละครั้ง** วันที่ 1 ตอนตี 2 ไม่ลงกลางเดือน
- ส่วนลดร้าน/ซิม พนักงานให้ที่ POS/ตอนเช็กอิน ดูระดับจากบัตร — ระบบไม่คุม POS
- แลกแต้มได้ที่หน้ารางวัล (§11) · ยังไม่มีแต้มหมดอายุ
- แต้มเปลี่ยนผ่านรายการ `PointTransaction` เท่านั้น ยอดคงเหลือตรงกับผลรวมรายการเสมอ (ตรวจทุกคืน)

### 3.4 การแจ้งเตือนของระบบสมาชิก

ทุกข้อความอยู่ใน **การแจ้งเตือน** บนเว็บ (`/app/inbox` จุดแดงบอกจำนวนที่ยังไม่อ่าน) และส่งทางอีเมลด้วยถ้าสมาชิกใส่อีเมลและไม่ได้ปิด · เมื่อเปิด LINE ส่งทาง LINE แทนอีเมล

| ข้อความ | ส่งเมื่อ |
|---|---|
| ต้อนรับ + รหัสสมาชิก + แต้มต้อนรับ | สมัครเสร็จ |
| ได้รับแต้มแล้ว — ยอด แต้มที่ได้ คงเหลือ อีกเท่าไรถึงระดับถัดไป | หลังนำเข้า POS · 1 ข้อความต่อคนต่อรอบ รวมทุกบิล |
| ยินดีด้วย เลื่อนระดับ + สิทธิ์ใหม่ | ยอดถึงเกณฑ์ |
| สุขสันต์เดือนเกิด + แต้มคูณ + โบนัสวันเกิด (ถ้าตั้ง) | ต้นเดือนเกิด ปีละครั้ง (งานกลางคืน · โบนัสจ่ายผ่านสมุดแต้ม) |

### 3.5 หลังบ้าน — สมาชิก

- **ค้นหา** ชื่อ / เบอร์ / รหัส · กรองระดับ · ช่องทางสมัคร (ตัวกรอง LINE แสดงเมื่อเปิด LINE)
- **ข้อมูลลูกค้าในหน้าเดียว** — รูป ชื่อ ระดับ แต้ม ยอด 12 เดือน ความคืบหน้าสู่ระดับถัดไป สิทธิ์ของระดับ · แท็บ ไทม์ไลน์ · บิล (กางดูรายการสินค้า) · แต้ม · การจองซิม · ตัวตนและ PDPA · บันทึกการแก้ไข
- **เพิ่มสมาชิกที่เคาน์เตอร์** — ได้แต้มต้อนรับเหมือนสมัครบนเว็บ · ลูกค้าเข้าสู่ระบบบนเว็บด้วยเบอร์นั้นได้ทันที · เบอร์ซ้ำพาไปข้อมูลเดิม · แนบรูปได้
- **ลิงก์ + QR สมัครสมาชิก** สำหรับตั้งที่เคาน์เตอร์ (ลิงก์เดียวกับปุ่ม A+B)
- **ปรับแต้ม** — ต้องมีเหตุผล (ลูกค้าเห็นในประวัติ) · ผู้จัดการสาขา/บริการลูกค้า ครั้งละไม่เกิน ±1,000 · ผู้ดูแลระบบไม่จำกัด
- **แก้ข้อมูล** รวมเปลี่ยนเบอร์ · **รูปโปรไฟล์** เก็บแบบส่วนตัว
- **รวมบัญชีซ้ำ** (ผู้ดูแลระบบ) · **ลบข้อมูล PDPA** (ผู้ดูแลระบบ) · บริการลูกค้าส่ง **คำขอ** เข้าคิวตรวจสอบ

เงินเก็บเป็น **สตางค์ (จำนวนเต็ม)** ทุกคอลัมน์ที่ลงท้าย `Satang` · เวลาธุรกิจเป็นเวลากรุงเทพฯ

### 4.2 กติกาข้อมูล

- **1 เบอร์ / 1 LINE UID ผูกได้สมาชิกคนเดียว** (unique ในฐานข้อมูล)
- **รหัสสมาชิก** `MST` + 8 หลักเรียงลำดับ ไม่เปลี่ยน ไม่นำกลับมาใช้
- **กันจองซ้อน** ในฐานข้อมูล: 1 lane 1 ชั่วโมงมีการจองที่ยังมีผลได้ 1 รายการ
- **แต้มต้อนรับให้ครั้งเดียวต่อคน** และ **แต่ละบิลให้แต้มครั้งเดียว** — บังคับในฐานข้อมูล
- **รวมบัญชี**: บัญชีที่เก็บไว้ได้ตัวตน บิล การจอง ประวัติ แต้ม (หักแต้มต้อนรับที่ได้ซ้ำ) · ผูก LINE คนละบัญชีทั้งคู่ = รวมไม่ได้
- **ลบข้อมูล PDPA**: ลบตัวตน ชื่อ วันเกิด อีเมล รูป · ยกเลิกการจองที่ยังไม่ถึงเวลา · บิลเก็บไว้ทางบัญชีแต่ไม่ผูกตัวบุคคล · เบอร์นั้นสมัครใหม่ได้
- ทุกการกระทำของพนักงานที่แก้สมาชิก แต้ม การจอง การนำเข้า การตั้งค่า เขียน **บันทึกการใช้งาน** (ใคร อะไร ก่อน/หลัง เหตุผล IP)

| ช่องเวลา | 1 ชั่วโมงตรงชั่วโมง ตามเวลาเปิดร้าน (ตั้งต่อวันในสัปดาห์) |

### 5.2 ลูกค้าจอง (`/app/booking` — ปุ่ม D หรือเว็บ)

```
เลือกวัน → ตาราง lane × ชั่วโมง (ว่าง · เต็ม · ปิด · ผ่านไปแล้ว — ไม่บอกว่าใครจอง)
 → แตะช่อง → จำนวนคน → ถือช่อง 5:00 นับถอยหลัง + ราคา
 → ยืนยัน → แจ้งยืนยัน (เว็บ + อีเมล) · เตือนก่อนเวลา
 ยังไม่เป็นสมาชิก → พาไปสมัคร แล้วกลับมาหน้าจอง
 "การจองของฉัน" อยู่หน้าเดียวกัน ยกเลิกได้ตามกติกา
```

### 5.3 การแจ้งเตือนของระบบจอง

ยืนยันการจอง · เตือนก่อนเวลา (ส่งครั้งเดียว ข้ามถ้าจองภายในช่วงเตือน) · ยกเลิก (ลูกค้าหรือพนักงาน พร้อมเหตุผล) · ย้ายเวลา/lane

### 5.4 หลังบ้าน — ซิมกอล์ฟ

- ตาราง **รายวัน** (lane × ชั่วโมง) และ **รายสัปดาห์** · ป้ายสีตามสถานะ และป้ายที่มา LINE / เว็บไซต์ / Walk-in / โทรจอง
- แตะช่องว่าง → จองให้ (ค้นสมาชิก หรือชื่อ+เบอร์) · เลือกเช็กอินเลยได้
- **ลากการ์ด** ย้ายเวลา/lane · ช่องปลายทางไม่ว่างย้ายไม่ได้
- แตะการจอง → เช็กอินพร้อมยอดที่รับ · บันทึกยอด · ไม่มาตามนัด · ยกเลิก (เหตุผลส่งถึงลูกค้า)
- **ปิด lane** (ซ่อม · ส่วนตัว · อีเวนต์) — มีการจองทับอยู่ต้องย้ายก่อน · แตะช่วงที่ปิดเพื่อเปิดคืน
- **รายการวันนี้** สำหรับเคาน์เตอร์ พร้อมปุ่มเช็กอิน · อัปเดตเองทุก 15 วินาที
- เปิดจากหน้าสมาชิก "จองซิมให้" ได้

## 10 · ความปลอดภัย การสำรองข้อมูล และงานตามเวลา

## 11 · รางวัลและคูปอง

สมาชิกใช้แต้มแลกจากแคตตาล็อกที่ MST ตั้งในหลังบ้าน (รางวัล › แคตตาล็อก) บนเว็บที่ `/app/rewards` — แท็บ รางวัล · คูปอง · คำขอ

| | คูปอง (COUPON) | ของรางวัล (PHYSICAL) เช่น iPad |
|---|---|---|
| ตั้งค่า | มูลค่า · ยอดขั้นต่ำ · อายุ (วันหลังแลก) | ระยะเวลาที่แจ้งลูกค้า เช่น 7–14 วัน |
| ทั้งสองแบบ | แต้มที่ใช้ · สต็อก (ว่าง = ไม่จำกัด) · แลกได้คนละกี่ครั้ง · เฉพาะระดับ · ช่วงวันที่เปิดแลก · เงื่อนไข · รูป · เปิด/ปิด | |
| ตอนแลก | ออกคูปองทันที รหัส `MST-XXXX-XXXX` + QR | สร้างคำขอ + Redemption ID `RD-000123` · เลือกรับที่ร้านหรือจัดส่ง |
| แจ้งใคร | สมาชิก (เว็บ + อีเมล) | สมาชิก (เว็บ + อีเมล) + อีเมลถึง Marketing |
| ต่อจากนั้น | พนักงานตรวจที่ **ตรวจคูปอง** (สแกน/พิมพ์) → กด ใช้คูปอง → ลดราคาใน POS เอง | คำขอใหม่ → กำลังตรวจสอบ → อนุมัติ → กำลังเตรียมของ → จัดส่งแล้ว (ต้องมีเลขพัสดุ) → เสร็จสิ้น |

**กติกา**
1. แต้มหักทันทีที่แลก (`REDEEM` ในสมุดแต้ม ผูกกับรายการแลก) — สมาชิกเห็นยอดคงเหลือจริงเสมอ
2. ไม่อนุมัติ / ยกเลิก → คืนแต้มเต็มจำนวน (`REDEEM_REFUND`) + คืนสต็อก + แจ้งสมาชิกพร้อมเหตุผล (ต้องใส่เหตุผล)
3. สมาชิกยกเลิกคำขอเองได้เฉพาะตอนยังเป็น "คำขอใหม่" · คูปองแลกแล้วยกเลิกเองไม่ได้ (พนักงานยกเลิกให้ได้ = คืนแต้ม)
4. คูปองใช้ได้ครั้งเดียวทุกสาขา — สแกนซ้ำจะขึ้นว่าใช้ไปแล้วเมื่อไร ที่ไหน บิลไหน · หมดอายุ = ไม่คืนแต้ม (งานกลางคืนเปลี่ยนสถานะ)
5. เช็กแต้มพอ · สต็อก · จำกัดต่อคน · ระดับ ในธุรกรรมเดียวกับการหักแต้ม (ล็อกแถวสมาชิก กดซ้ำไม่หักสองครั้ง)
6. ทุกการเปลี่ยนสถานะเก็บว่าใคร เมื่อไร ข้อความอะไร (ประวัติในหน้าคำขอ + บันทึกการใช้งาน) · คนแรกที่ขยับสถานะเป็นเจ้าของเคส
7. อีเมลถึง Marketing มีแค่ Redemption ID รหัสสมาชิก รางวัล แต้ม วิธีรับ และลิงก์เปิดเคส — **ไม่มีชื่อ เบอร์ ที่อยู่** (ดูในหลังบ้านที่มีสิทธิ์เท่านั้น) · ส่งผ่าน Resend (`RESEND_API_KEY`, `EMAIL_FROM`) ถ้ายังไม่ตั้งจะข้ามแต่คำขอยังเข้าคิวตามปกติ
8. ลบข้อมูล PDPA → ลบที่อยู่จัดส่ง ยกเลิกคูปองที่ยังไม่ใช้ · รวมบัญชี → ย้ายรายการแลกไปบัญชีหลัก

**รายงาน** (รางวัล › รายงาน · 30/90 วัน/12 เดือน): แต้มที่ออก · แต้มที่ใช้แลก (หักคืนแล้ว) · จำนวนแลก · คำขอค้าง · คูปองออก/ใช้ · อัตราการใช้คูปอง · เวลาส่งของเฉลี่ย · แยกตามรางวัล

**ช่องทางออนไลน์:** คำสั่งซื้อจาก mstgolf.co.th (Shopify) ได้แต้มเหมือนหน้าร้านหลังพ้นช่วงคืนสินค้า — ตั้งค่าที่ ตั้งค่า › ร้านออนไลน์ (`docs/th-commerce/INTEGRATION.md`)
